## 1. 快速迁移清单

### 必须改（C）

| 旧 API | 新 API | 迁移动作 |
|---|---|---|
| `Channel.order: i32` | `Channel.order: u64` | 直接读取；不要按数值排序，用 `ChannelTree` |
| `ChannelBuilder::order(i32)` | `ChannelBuilder::order(u64)` | 传 `u64`，或 `order as u64` |
| Java `Channel.order: int` | `Channel.order: long` | 读取处改用 `long` |
| Python `Channel.order`（i32 范围） | `u64` 范围 | Python 侧仍表现为 `int`，大频道 id 不再截断 |
| `Error` 新增 `InvalidArgument(String)` | — | Rust 对 `Error` 做穷举 match 的地方补 `_` 分支 |
| `Error` 新增 `FileTransferCorrupted(String)` | — | 同上 |
| `AudioConfig` 新增 `decoder_pool` 字段 | — | 用 `..Default::default()` 构造；穷举字段的字面量需补该字段 |
| `Event::AudioReceived.data: Vec<u8>` | `Arc<[u8]>` | 读取处 `&data` 仍可自动解引用为 `&[u8]`；构造处改 `Arc::from(vec)` |
| `Channel` 新增 `max_clients_kind`/`max_family_clients_kind` | — | 字面量加 `..Default::default()`；`max_clients` 保留 |
| `Channel` 新增 `permission_hints_known` | — | 同上 |
| `Event::ChannelPermissionsUpdated` 新增 `known` | — | match 该变体处补字段；Java/Python 事件字典新增 `known` |
| `Event::TextMessage` 新增 `target_id` | — | match 补字段或用 `..` |
| `User` 新增 `created_at`/`last_connected_at` | — | 字面量用 `..Default`；Java `User` 构造器末尾加两个 `Long` |
| `Client::users()`/`channels()` 返回 `Arc<[T]>` | — | 读取不变；需要 `Vec` 时 `.to_vec()` |

### 建议改（B）

| 旧行为 | 新行为 | 建议 |
|---|---|---|
| 下载 >10 MB 静默截断 | 默认上限 64 MiB，超限发 `FileTransferFailed` | 大文件请调高 `FileTransferConfig::max_memory_download` 或等待流式 API |
| 文件读写 5 s/10 s 总超时 | 每 chunk 30 s 空闲超时 | 慢链路不再因总时长失败 |
| `send_audio` 超大帧交给底层 | 超过单 UDP 包容量返回 `InvalidArgument` | 检查编码帧大小 |
| whisper 目标超量静默截断 | 超过 32 client / 255 channel 返回 `InvalidArgument` | 检查目标数量 |
| `disconnect()` 后仍可能发送 | 所有发送 API 返回 `NotConnected` | 断开后不要继续调用发送 API |
| `wait_connected` 丢弃握手期事件 | 缓存到下一次事件泵 | 无需改；消息不再丢 |
| `Connected` 可能发两次 | 只在状态同步后发一次 | 检查事件计数逻辑 |
| `channel_password`/`hardware_id`/`connect_timeout` 配置无效 | 已接线并生效 | 无需改；密码频道/自定义硬件 ID 现在可用 |
| 非 Opus 频道被当 Opus 解码 | 返回 `AudioError::UnsupportedCodec` | 检查频道 codec；不要期待 Speex/CELT 音频 |
| Bot 收不到消息 | Bot 驱动 `wait_events` | 无需改；命令现在会触发 |
| Bot owner-only 永远失败 | 通过发送者 UID 判断 | 配置 `owners` 后生效 |
| 插件命令未注册 | 加载插件时注册 `commands()` | 无需改 |
| 文件命令忽略频道密码 | 新增 `*_with_password` 方法并透传 | 密码频道用新方法；旧方法保持无密码 |
| Java `moveToChannel` 无密码参数 | 新增 `moveToChannel(long, String)` 重载 | 旧调用不变；密码频道用新重载 |
| BBCode HTML 直接拼接 | 文本/属性转义，危险 URL/颜色/字号降级 | 不要对输出再次 HTML 转义；不要依赖 `javascript:` 链接 |
| `ChannelTree` 按 order 数值排序 | 按 `channel_order` 前驱链排序 | 无需改；树顺序更接近官方客户端 |
| 用户离开后解码器常驻 | `UserLeft` 可转给 `AudioManager::handle_event` 清理；空闲超时与数量上限自动淘汰 | 使用 `AudioManager` 时把客户端事件逐条/批量转给它 |
| 上传流结束即发 `FileUploaded` | 先 `ftgetfileinfo` 校验大小，再发成功/失败事件 | 等待事件；不要假设流结束即完成 |

### 无需改（A）

- 新增 `FileTransferConfig`、`Client::set_file_transfer_config`、`Client::file_transfer_config`。
- 新增 `FileTransferConfig::unlimited()`。
- 新增 `DecoderPoolConfig`、`AudioConfig::decoder_pool`、`AudioManager::handle_event` / `handle_events` / `evict_idle_decoders` / `decoder_count`。
- 新增 `SampleBufferPool`、`CaptureDevice::start_with_pool`。
- 新增 `AudioStats`、`CaptureStats`、`PlaybackStats` 及对应 `stats()`。
- `Channel` 其他字段、事件结构未变。

### 代码对比

```rust
// 旧（编译失败）
let channel = Channel {
    order: 12i32,
    ..Default::default()
};

// 新
let channel = Channel {
    order: 12u64,
    ..Default::default()
};
```

```java
// 旧
int order = channel.order;

// 新
long order = channel.order;
```

```python
# 旧/新代码不变；值域从 i32 变为 u64
order = channel.order
```

```rust
// 旧：离开的用户仍保留解码器
for event in client.wait_events(100).await? {
    // ...
}

// 新：把事件交给 AudioManager，UserLeft 会释放该用户的解码器与混音缓冲
for event in client.wait_events(100).await? {
    audio.handle_event(&event).await;
    // ...
}
```

## 3. 返回结构变更

| 结构 | 字段 | 旧类型 | 新类型 | 旧含义 | 新含义 | 迁移 |
|---|---|---|---|---|---|---|
| `Channel` | `order` | `i32` | `u64` | 被截断的排序值 | 前驱频道 id（0 表示第一个） | 不要按数值排序；用 `ChannelTree` |
| Java `Channel` | `order` | `int` | `long` | 同上 | 同上 | 读取处改 `long` |
| Python `Channel` | `order` | `i32` | `u64` | 同上 | 同上 | 同上 |
| `Event::AudioReceived` | `data` | `Vec<u8>` | `Arc<[u8]>` | 独占音频负载 | 共享音频负载，广播/返回事件不再深拷贝 | 读取不变；构造用 `Arc::from` |
| `Event::AudioReceived` | `seq` | 不存在 | `u16` | 无序号 | 发送方语音包序号 | 用于检测丢帧/PLC |

## 5. 行为语义变更（签名不变也要写）

| ID | API/事件 | 旧行为 | 新行为 | 影响 | 迁移 |
|---|---|---|---|---|---|
| BHV-010 | 文件下载 | 超过 10 MiB 截断，仍发 `FileDownloaded` | 超过 `max_memory_download` 发 `FileTransferFailed` | 旧代码可能收到新错误 | 调高上限或等流式 API |
| BHV-011 | 文件读写超时 | 下载 5 s、上传 10 s 总超时 | 每 64 KiB chunk 30 s 空闲超时 | 慢链路可完成 | 无需改 |
| BHV-012 | 上传 resume offset | 超出数据长度时静默截断 | 发 `FileTransferFailed` | 服务器异常可感知 | 无需改 |
| BHV-013 | `Client::send_audio` | 超大帧交给底层 | 超过单 UDP 包容量返回 `InvalidArgument` | 需要检查帧大小 | 编码器输出上限 |
| BHV-014 | `Client::set_whisper_targets` | 超量目标交给底层截断 | >32 client / >255 channel 返回 `InvalidArgument` | 需要检查目标 | 分批发送 |
| BHV-015 | 断开后的发送 API | 可能仍交给残留连接 | 返回 `Error::Connection(NotConnected)` | 行为更严格 | 断开后停止发送 |
| BHV-016 | `Client::wait_connected` | 丢弃非 BookEvents | 缓存到下一次 `process_events`/`wait_events` | 握手期消息不丢 | 无需改 |
| BHV-017 | `BBCodeParser::to_html` | 原文直接拼 HTML | 文本/属性转义；拒绝危险 URL/颜色/字号 | 输出更安全 | 不要二次转义 |

| BHV-021 | `ClientConfig.channel_password/hardware_id/connect_timeout` | 未消费 | 已传入连接/超时逻辑 | 配置开始生效 | 密码频道、自定义 HWID、连接超时可用了 |
| BHV-022 | `AudioManager::process_incoming` | 忽略 codec，一律 Opus | 仅 4/5 解码，其他返回 `UnsupportedCodec` | 非 Opus 频道不再输出噪声 | 检查 codec 并处理错误 |
| BHV-023 | `Bot::run` | 不驱动事件流，收不到消息 | 每轮调用 `wait_events` | Bot 命令开始工作 | 无需改 |
| BHV-024 | Bot owner-only / 插件命令 | owner-only 永远失败；插件命令未注册 | 用发送者 UID 判断；加载时注册命令 | 权限与插件生效 | 配置 `owners`、实现 `Plugin::commands()` |
| BHV-025 | `BotConfig.password/channel/channel_password` | 创建 Client 时丢弃 | 传入 `ClientConfig` | 默认频道/密码配置生效 | 无需改 |
| BHV-026 | Java `moveToChannel` | 只有 `(long)` | 新增 `(long, String)` 重载 | 密码频道可用 | 需要密码时用新重载 |
| BHV-027 | 文件命令 | `cpw`/`tcpw` 固定空串 | 新增 `*_with_password` 并编码密码 | 密码频道文件操作可用 | 需要密码时用新方法 |
| BHV-028 | 文件列表/权限查询 | 单槽 pending，并发互相覆盖 | 按 `return_code` 关联，支持并发；同键重复请求报错 | 并发请求可靠 | 无需改 |
| BHV-029 | `Client::move_to_channel` | 发送后立即写 `channel_id` | 只在服务器 `ClientChannel` 变更后更新 | 失败时本地状态不再错误 | 无需改 |
| BHV-030 | 重连 | 订阅/静音/状态不恢复 | 首个 `BookEvents` 后重订阅、同步、恢复静音，发 `Reconnected` | 重连后状态一致 | 监听 `Reconnected` |
| BHV-031 | FFI | 无事件泵 | 新增 `tslib_client_pump` 等 | C 连接可推进 | 主循环调用 pump |
| BHV-032 | `User` 字段 | `country/description=None`，`idle/connected=0` | 映射 D 的 `country_code/description/connection_data` | 信息更完整 | 无需改 |
| BHV-033 | `ServerInfo` 字段 | `uid` 空、banner 未赋值 | 按版本算 SHA-1/SHA-256 UID，映射 banner | 服务器信息完整 | 无需改 |
| BHV-034 | 用户离开事件 | 一律 `UserLeft` | 按 reason 发 `UserKickedFromChannel`/`UserKickedFromServer`/`UserBanned`；自身移动发 `ChannelJoined` | 事件更精确 | 监听新事件 |
| BHV-035 | 文件权限提示 | 权限缺失默认允许；查询失败默认 browse/download | 缺失视为未授予；失败只保留 join hint | UI 不再显示不可用操作 | 无需改 |
| BHV-036 | `User.is_talking` | 恒 `false` | 随音频/TalkStatus 维护 | 说话状态可直接用 | 无需改 |
| BHV-037 | `AudioManager` 解码器生命周期 | 每个用户首次音频创建后常驻 | `UserLeft` 可清理；空闲超时/数量上限自动淘汰；LRU 优先 | 长会话内存有界 | 事件转给 `handle_event(s)`，或定期 `evict_idle_decoders` |
| BHV-038 | `AudioManager::process_incoming` 解码器创建失败 | `unwrap` panic | 返回 `AudioError` | 错误可被调用方处理 | 处理 `Err` 分支 |
| BHV-039 | `ClientConfig` / `ClientConfigBuilder` 的 `Debug` | 输出明文 `password`/`channel_password` | 输出 `<redacted>` | 日志不再泄露密码 | 不要依赖 `Debug` 获取密码原文 |
| BHV-040 | 上传完成事件 | 传输流结束立即发 `FileUploaded` | 先发 `ftgetfileinfo`；大小一致才发 `FileUploaded`，不一致发 `FileTransferFailed`（`FileTransferCorrupted`）；无浏览权限（2568）warning 后仍发 `FileUploaded` | 事件晚一个往返到达，但能发现落盘损坏 | 等待事件即可；不要假设流结束即完成 |
| BHV-041 | Python `Client.server_info()` | 返回上次同步的缓存 | 读取当前 bookkeeping 状态 | 在线数/uptime 实时 | 无需改 |
| BHV-042 | Python 事件字典 | `audio_received`/`file_downloaded` 只有长度；文件列表只有数量 | 增加 `data`（bytes）与 `files`（字典列表） | 负载可直接使用 | 旧键保留，新增键可选用 |
| BHV-043 | JNI `file_list_received.files` | 手拼 JSON，只转义引号/反斜杠 | `serde_json` 序列化，控制字符也合法 | 特殊文件名可解析 | 仍是 JSON 字符串；用 JSON 库解析 |
| BHV-044 | 日志内容 | 发送消息/私聊/poke 输出正文；JNI 发布版 `Trace` | 只输出长度；发布版 `Info` | 日志不再泄露聊天内容，发布包日志量下降 | 不要依赖日志内容调试消息 |
| BHV-045 | 音频回调锁 | 采集/播放回调阻塞等待 `Mutex` | `try_lock`；播放取不到 mixer 锁时输出静音，采集取不到缓冲锁时丢弃本次回调 | 实时线程不再被网络/解码线程阻塞，极端争用下可能出现短暂静音/丢帧 | 无需改；不要假设每个回调帧都会送达 |
| BHV-046 | `Channel::is_full` / `joinable_channels` | 仅看 `max_clients`，`-1` 一律视为不限，无法区分 Inherited；joinable 不检查人数 | `is_full` 优先用结构化上限；新增按用户/占用数的 joinable 变体，`Inherited` 沿父链解析 | 满员频道可正确排除 | 有用户列表时用 `joinable_channels_for_users` |
| BHV-047 | 权限查询失败 | 回退 `JOIN` 提示，UI 无法区分未知 | `known=false`、`bits=0`；成功响应 `known=true` | 失败时不再显示可加入提示 | 检查 `known` 再显示文件/加入操作 |
| BHV-048 | `ChannelTree::remove_channel` / `update_channel` | 只删单个节点，子节点变孤儿；update 可能重复挂载或成环 | 删除整棵子树；update 重建结构并拒绝环；路径/打印遇环终止 | 本地树与服务器一致，不会死循环 | 删除后不要继续使用被删子频道；需要明细用 `remove_subtree` |
| BHV-049 | 语音接收路径 | 每包立即解码播放，乱序/丢包无补偿 | 新入口固定 60 ms 缓冲：迟到丢弃、gap 最多 3 帧 PLC、超限跳到下一个真实包；旧入口仍直通 | 延迟可预测，抖动/丢包有补偿 | 需要 jitter 时改用 `process_incoming_with_seq` + `pump_jitter` |
| BHV-050 | `users()` / `channels()` | 每次调用全量克隆 `Vec` | 返回缓存 `Arc`，事件泵/状态变更后重建 | UI 多次读取零克隆 | 不要依赖每次调用返回新 `Vec`；需要独立副本时 `.to_vec()` |
| BHV-051 | 初始输入静音 | 连接后硬编码 `true` | 由 `initial_input_muted` 控制，默认仍 `true` | 开麦客户端可配置 | 需要开麦时设 `false` |
| BHV-052 | 临时断线 | 无超时提示，可能长时间停留在 `Reconnecting` | 超过 `reconnect_watchdog` 发一次 `ConnectionStalled`，状态仍为 `Reconnecting` | 应用可提示“重连中/卡住” | 监听新事件；不要据此判定连接已断开 |
| BHV-053 | 事件分发（actor） | 广播满时控制事件可能丢；慢 handler 阻塞泵 | 控制事件用无界队列不丢；语音用有界广播 drop-oldest 并计数 | 控制事件可靠，慢消费者只影响语音 | 用 `ActorEventStream::dropped_voice_events` 观测 |
| BHV-054 | Python `Client` | 同步 Client + 阻塞事件泵 | 构造函数完成连接；`process_events` 非阻塞、新增 `wait_events` | Python 主线程不再被事件泵阻塞 | `wait_connected()` 变为立即返回 |

## 6. 绑定层变更

### 6.1 Java / JNI

| 项 | 旧 | 新 | 迁移 |
|---|---|---|---|
| `Channel.order` | `int` | `long` | 读取处改 `long` |
| `Client.moveToChannel` | `(long)` | `(long)` + `(long, String)` | 旧调用不变；密码频道用新重载 |
| `Client.waitEvents` | 未声明 | `(int timeoutMs)` 返回 `Event[]` | 可直接阻塞等待事件 |
| `Client.sendPoke` | 未声明 | `(int userId, String msg)` | 可直接使用 |
| `Client.getNetworkStats` | 未声明 | 返回 `double[]` 或 `null` | 可直接使用 |
| `Client.updateServerVariables` | 未声明 | 无参 | 可直接使用 |
| `Client.setWhisperTargets` | 未声明 | `(int[] clients, long[] channels)` | 可直接使用 |
| `Client.setAudioSink` | 未声明 | `(AudioSink)` | 新增 `AudioSink` 接口 |
| `Identity.exportTeamSpeakIni` | 未声明 | `(String label)` | 可直接导出 ts.ini |
| `OpusCodec.decodePlc/setBitrate/setFec/setExpectedPacketLoss` | 未声明 | 已补齐 | 可直接使用 |
| `EchoCanceller` | 无 Java 类 | 新增 | 可直接使用 AEC3 |
| JNI `Channel` 构造描述符 | `...;IZZZZ...` | `...;JZZZZ...` | 无需调用方改；确保 native 与 Java 同步 |
| Java `Channel` 构造器 | `(..., long permissionHints)` | `(..., long permissionHints, boolean permissionHintsKnown)` | 直接构造 `Channel` 的下游需补最后一个参数 |
| Java `Channel.permissionHintsKnown` | 不存在 | 新增 `boolean` 字段 | 读取即可；`false` 表示权限未知 |
| Java `User` 构造器 | `(..., long iconId)` | `(..., long iconId, Long createdAt, Long lastConnectedAt)` | 直接构造 `User` 的下游需补两个参数 |
| Java `User.createdAt/lastConnectedAt` | 不存在 | 新增 `Long` 字段 | 读取即可；`null` 表示未知 |
| Java `ActorClient` | 不存在 | 新增类：`pumpEvents`、带超时的命令、`state` | 需要命令结果/后台事件泵时使用 |
| JNI `nativeMoveToChannel` | `(long, long)` | `(long, long, String)` | Java 重载已适配 |
| `ChannelTree` | `(long) ch.order` | 仍可用 | 可选去掉冗余 cast |

### 6.2 Python

| 项 | 旧 | 新 | 迁移 |
|---|---|---|---|
| `Channel.order` | `i32` | `u64` | Python 仍看到 `int`；大 id 不截断 |
| `Channel.permission_hints` / `permission_hints_known` | 不存在 | 新增字段 | 读取即可；`known=False` 表示权限未知 |
| `User.created_at` / `last_connected_at` | 不存在 | 新增字段（`int` 或 `None`） | 读取即可 |

### 6.3 C / FFI
