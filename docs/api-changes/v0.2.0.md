# API 变更说明 v0.2.0

| 项 | 内容 |
|---|---|
| 版本 | v0.2.0（未发布） |
| 日期 | 2026-11-05 |
| 兼容级别 | C（Breaking signature）+ B（Behavioral） |
| 影响 crate | `tslib-core`、`tslib-channel`、`tslib-chat`、`tslib-jni`、`tslib-python` |
| 影响绑定 | Rust / Java / Python / C（行为同步） |
| 关联 spec | `docs/spec-error-fixes-performance.md` 第 4 节 B1 |
| 状态 | 随 B1 增量更新；后续批次继续追加 |

## 1. 快速迁移清单

### 必须改（C）

| 旧 API | 新 API | 迁移动作 |
|---|---|---|
| `Channel.order: i32` | `Channel.order: u64` | 直接读取；不要按数值排序，用 `ChannelTree` |
| `ChannelBuilder::order(i32)` | `ChannelBuilder::order(u64)` | 传 `u64`，或 `order as u64` |
| Java `Channel.order: int` | `Channel.order: long` | 读取处改用 `long` |
| Python `Channel.order`（i32 范围） | `u64` 范围 | Python 侧仍表现为 `int`，大频道 id 不再截断 |
| `Error` 新增 `InvalidArgument(String)` | — | Rust 对 `Error` 做穷举 match 的地方补 `_` 分支 |

### 建议改（B）

| 旧行为 | 新行为 | 建议 |
|---|---|---|
| 下载 >10 MB 静默截断 | 默认上限 64 MiB，超限发 `FileTransferFailed` | 大文件请调高 `FileTransferConfig::max_memory_download` 或等待流式 API |
| 文件读写 5 s/10 s 总超时 | 每 chunk 30 s 空闲超时 | 慢链路不再因总时长失败 |
| `send_audio` 超大帧交给底层 | 超过单 UDP 包容量返回 `InvalidArgument` | 检查编码帧大小 |
| whisper 目标超量静默截断 | 超过 32 client / 255 channel 返回 `InvalidArgument` | 检查目标数量 |
| `disconnect()` 后仍可能发送 | 所有发送 API 返回 `NotConnected` | 断开后不要继续调用发送 API |
| `wait_connected` 丢弃握手期事件 | 缓存到下一次事件泵 | 无需改；消息不再丢 |
| BBCode HTML 直接拼接 | 文本/属性转义，危险 URL/颜色/字号降级 | 不要对输出再次 HTML 转义；不要依赖 `javascript:` 链接 |
| `ChannelTree` 按 order 数值排序 | 按 `channel_order` 前驱链排序 | 无需改；树顺序更接近官方客户端 |

### 无需改（A）

- 新增 `FileTransferConfig`、`Client::set_file_transfer_config`、`Client::file_transfer_config`。
- 新增 `FileTransferConfig::unlimited()`。
- `Channel` 其他字段、事件结构未变。

## 2. 方法签名变更

| ID | 模块/方法 | 旧签名 | 新签名 | 级别 | 迁移片段 | 绑定影响 |
|---|---|---|---|---|---|---|
| API-001 | `tslib_channel::ChannelBuilder::order` | `fn order(self, order: i32) -> Self` | `fn order(self, order: u64) -> Self` | C | `.order(prev_id as u64)` | Java/Python 无 Builder 暴露 |
| API-002 | `tslib_core::Error` | 无 `InvalidArgument` | `InvalidArgument(String)` | C | match 补 `_` | JNI/Python 通过 `to_string()`，无需改 |
| API-003 | Java `Channel` 构造器 | `(..., int order, ...)` | `(..., long order, ...)` | C | 见下 | JNI 描述符同步改为 `J` |
| API-004 | Python `PyChannel.order` | `i32` | `u64` | C（值域） | 无需改代码 | Python `int` |

### 代码对比

```rust
// 旧（编译失败）
let channel = Channel {
    order: 12i32,
    ..Default::default()
};

// 新
let channel = Channel {
    order: 12u64,
    ..Default::default()
};
```

```java
// 旧
int order = channel.order;

// 新
long order = channel.order;
```

```python
# 旧/新代码不变；值域从 i32 变为 u64
order = channel.order
```

## 3. 返回结构变更

| 结构 | 字段 | 旧类型 | 新类型 | 旧含义 | 新含义 | 迁移 |
|---|---|---|---|---|---|---|
| `Channel` | `order` | `i32` | `u64` | 被截断的排序值 | 前驱频道 id（0 表示第一个） | 不要按数值排序；用 `ChannelTree` |
| Java `Channel` | `order` | `int` | `long` | 同上 | 同上 | 读取处改 `long` |
| Python `Channel` | `order` | `i32` | `u64` | 同上 | 同上 | 同上 |

## 4. 类型、字段、枚举变更

| 项 | 旧 | 新 | 级别 | 说明 |
|---|---|---|---|---|
| `Channel.order` | `i32` | `u64` | C | 大频道 id 不再溢出 |
| `Error` | 8 个变体 | 新增 `InvalidArgument(String)` | C | 调用方参数错误 |
| `FileTransferConfig` | 不存在 | 新增 | A | 默认 64 MiB / 30 s idle / 64 KiB chunk |
| `ClientConfig` | 不变 | 不变 | — | 文件配置通过 `Client::set_file_transfer_config` 设置 |

## 5. 行为语义变更（签名不变也要写）

| ID | API/事件 | 旧行为 | 新行为 | 影响 | 迁移 |
|---|---|---|---|---|---|
| API-010 | 文件下载 | 超过 10 MiB 截断，仍发 `FileDownloaded` | 超过 `max_memory_download` 发 `FileTransferFailed` | 旧代码可能收到新错误 | 调高上限或等流式 API |
| API-011 | 文件读写超时 | 下载 5 s、上传 10 s 总超时 | 每 64 KiB chunk 30 s 空闲超时 | 慢链路可完成 | 无需改 |
| API-012 | 上传 resume offset | 超出数据长度时静默截断 | 发 `FileTransferFailed` | 服务器异常可感知 | 无需改 |
| API-013 | `Client::send_audio` | 超大帧交给底层 | 超过单 UDP 包容量返回 `InvalidArgument` | 需要检查帧大小 | 编码器输出上限 |
| API-014 | `Client::set_whisper_targets` | 超量目标交给底层截断 | >32 client / >255 channel 返回 `InvalidArgument` | 需要检查目标 | 分批发送 |
| API-015 | 断开后的发送 API | 可能仍交给残留连接 | 返回 `Error::Connection(NotConnected)` | 行为更严格 | 断开后停止发送 |
| API-016 | `Client::wait_connected` | 丢弃非 BookEvents | 缓存到下一次 `process_events`/`wait_events` | 握手期消息不丢 | 无需改 |
| API-017 | `BBCodeParser::to_html` | 原文直接拼 HTML | 文本/属性转义；拒绝危险 URL/颜色/字号 | 输出更安全 | 不要二次转义 |
| API-018 | `ChannelTree` 顺序 | 按 `order` 数值升序 | 按前驱链还原；环/缺失前驱按 id 回退 | 顺序更接近官方客户端 | 无需改 |
| API-019 | `ChannelTree::add_channel` | 只追加，不重排 | 每次重建结构 | 重复/乱序插入更稳定 | 无需改 |

## 6. 绑定层变更

### 6.1 Java / JNI

| 项 | 旧 | 新 | 迁移 |
|---|---|---|---|
| `Channel.order` | `int` | `long` | 读取处改 `long` |
| JNI `Channel` 构造描述符 | `...;IZZZZ...` | `...;JZZZZ...` | 无需调用方改；确保 native 与 Java 同步 |
| `ChannelTree` | `(long) ch.order` | 仍可用 | 可选去掉冗余 cast |

### 6.2 Python

| 项 | 旧 | 新 | 迁移 |
|---|---|---|---|
| `Channel.order` | `i32` | `u64` | Python 仍看到 `int`；大 id 不截断 |
| 其他 | — | 不变 | — |

### 6.3 C / FFI

| 项 | 旧 | 新 | 迁移 |
|---|---|---|---|
| `Channel` 暴露 | FFI 当前不暴露 Channel 结构 | 不变 | — |
| 行为 | 文件截断/断开后发送 | 同 Rust 行为修正 | 通过 `tslib_client_*` 返回值感知 |
